Command-line reference
======================

Every option is written either as ``--option=value`` or as ``--option value``.
Options marked *required* must be given on every run.

Input
-----

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--intDir``
     - yes
     - —
     - Directory holding the intensity images. Values: path to an existing directory. Required even when ``--intSegMapFile`` is used: mapped intensity file names are resolved relative to this directory. When it is the same directory as ``--segDir``, Nyxus runs in whole-slide mode and treats each image as one ROI.
   * - ``--segDir``
     - yes
     - —
     - Directory holding the label (mask) images that define the ROIs. Values: path to an existing directory. Set it to the same directory as ``--intDir`` for whole-slide mode, where each intensity image is a single ROI and no mask is read. Required even with ``--intSegMapFile``: mapped mask file names are resolved relative to this directory.
   * - ``--filePattern``
     - no
     - ``.*``
     - Selects which files in the input directories are processed. In 2D the pattern must match the whole file name. Values: regular expression (2D); regular expression or file pattern with ``{d+}``, ``{c+}``, ``{set d+}`` (3D). A regular expression, so use ``.*\.tif`` rather than ``*.tif``. In 3D a pattern containing ``{set d+}`` is read as a z-slice file pattern, for example ``BRATS_{d+}_z{set d+}_t{d+}.ome.tif``. Such a pattern currently matches no files and the run stops with 'No intensity and/or label file pairs to process'. Not applied to pairs listed in an ``--intSegMapFile``.
   * - ``--intSegMapFile``
     - no
     - —
     - Names a text file that lists explicit intensity/mask pairs, one pair per line, instead of matching files by name. Values: file name inside ``--intSegMapDir``. Each line holds an intensity file name and then a mask file name, separated by whitespace. Intensity names are relative to ``--intDir`` and mask names to ``--segDir``. Requires ``--intSegMapDir``. ``--filePattern`` is not applied to listed pairs. 2D only.
   * - ``--intSegMapDir``
     - no
     - —
     - Directory that contains the ``--intSegMapFile`` pairing file. Values: path to an existing directory. Has no effect unless ``--intSegMapFile`` is also given.
   * - ``--dim``
     - no
     - ``2``
     - Sets whether the dataset is processed as 2D images or as 3D volumes. Values: 2 \| 3. In 3D the default feature set is ``*3D_ALL*``, the Gabor and nested-ROI options are rejected, and ``--intSegMapFile`` is ignored.

Output
------

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--outDir``
     - yes
     - —
     - Directory where result files are written. Values: path to an existing directory. The directory must already exist.
   * - ``--outputType``
     - yes
     - —
     - Selects the result format: one CSV per image pair, one combined CSV, an Arrow IPC file, or a Parquet file. Values: separatecsv \| singlecsv \| arrowipc \| parquet (case-insensitive). There is no default. arrowipc and parquet need a build with Arrow support.
   * - ``--resultFname``
     - no
     - ``NyxusFeatures``
     - Base name of the result file for singlecsv, arrowipc and parquet output. Values: non-empty file name without extension. Ignored with separatecsv, which names each file after its image pair.
   * - ``--noval``
     - no
     - ``0.0``
     - Value reported in place of a feature that cannot be computed (NaN or undefined). Values: real number. In Arrow and Parquet output, values that are still NaN or infinite when they are written become -0.0 instead, whatever ``--noval`` is. A non-numeric value stops the run with an error.
   * - ``--tinyval``
     - no
     - ``1e-10``
     - Accepted and validated, but no feature reads it. Values: real number. Intended as the small constant feature formulas use to avoid division by zero; the stored value is not used by any feature. A non-numeric value stops the run with an error.
   * - ``--aggr``
     - no
     - ``false``
     - When true, writes one row per image holding the mean of each feature over that image's ROIs, labelled ROI -1, instead of one row per ROI. Values: true \| false \| t \| f (case-insensitive). Applies only to CSV output (separatecsv or singlecsv) for images with masks. Arrow, Parquet and whole-slide output ignore it. Values the features substituted with ``--noval`` enter the mean at that value. A value still NaN at output time contributes the full ``--noval`` rather than ``--noval`` divided by the number of ROIs, and an infinite value is not replaced, so the aggregated cell can be inf.
   * - ``--annot``
     - no
     - ``false``
     - When true, adds annotation columns (anno0, anno1, ...) to CSV output. Their values come from the mask file name split at underscores. Values: true \| false \| t \| f (case-insensitive). Only the part of the mask file name before the first dot is used, and empty pieces are dropped. Annotation columns appear in CSV output only. With Arrow IPC or Parquet output, ``--annot=true`` currently stops the run with a crash and leaves an unreadable file (known defect, https://github.com/PolusAI/nyxus/issues/517).
   * - ``--annotsep``
     - no
     - ``_``
     - Separator for splitting file names into annotations. Values: string. The value is accepted but annotations are always split at '_'.

Features
--------

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--features``
     - no
     - ``*ALL* (2D) or *3D_ALL* (3D)``
     - Selects the features or feature groups to compute. Values: comma-separated feature and group names (case-insensitive), or the path of a text file listing them. If omitted, ``*ALL*`` (2D) or ``*3D_ALL*`` (3D) is computed; in 2D the ``IH_*`` features are then left out unless ``--ibsi=true``. If the value is the path of an existing file, the names are read from it: one or more per line, and ``#`` starts a comment. Names are case-insensitive. An unknown name stops the run and lists the valid names. Image-quality names cannot be mixed with other features. Intensity Histogram (``IH_*``) features need ``--ibsi=true``.
   * - ``--ibsi``
     - no
     - ``false``
     - Turns on IBSI compliance mode: texture families skip grey-level binning and follow IBSI definitions, and the Intensity Histogram family becomes available. Values: true \| 1 \| on (case-insensitive); any other value means false. Invalid values are not reported; they silently mean false.
   * - ``--mergerois``
     - no
     - ``false``
     - Merges all nonzero mask labels into one ROI covering the whole foreground, instead of one ROI per label. Values: true \| 1 \| on (case-insensitive); any other value means false. Background (label 0) is still excluded. Invalid values are not reported; they silently mean false.
   * - ``--skiproi``
     - no
     - ``no ROIs skipped``
     - Leaves ROIs with the listed labels out of feature calculation and output, either in every image or only in named mask files. Values: label[,label...] or maskfile:label[,label...][;maskfile:label...]. File names are mask file names without directories. A plain label list applies to every image and takes precedence over file-specific lists. Not used in whole-slide mode.
   * - ``--pixelDistance``
     - no
     - ``5``
     - Distance in pixels within which two ROIs count as neighbors, for the neighbor features. Values: integer >= 1.
   * - ``--pixelsPerCentimeter``
     - no
     - —
     - Image resolution, for reporting area in square micrometres (AREA_UM2). Values: real number > 0. The value is accepted and validated but does not reach the results: AREA_UM2 is reported as 0 whatever the resolution (known defect, https://github.com/PolusAI/nyxus/issues/496).
   * - ``--embeddedpixelsize``
     - no
     - —
     - Accepted for compatibility. Values: any string. The value is accepted and shown in the run summary but does not affect any result.
   * - ``--onlineStatsThresh``
     - no
     - —
     - Reserved option name. Values: not accepted. The name is reserved but the option is not accepted: passing it stops the run as an unrecognized argument.

Texture settings
----------------

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--coarseGrayDepth``
     - no
     - ``64``
     - Grey depth used to bin intensities for every 2D and 3D texture family, and the bin count of the ENTROPY, UNIFORMITY and HISTOGRAM histograms and of the Intensity Histogram (``IH_*``) family. Values: integer: > 0 MATLAB-style bins from 0 to the ROI maximum, < 0 \|n\| PyRadiomics-style bins over the ROI range, 0 no binning. A family's own greydepth metaparameter (set_metaparam in Python) overrides it for that family. NGLDM bins a positive value its own way, to levels 0 to n. The histograms use \|n\| bins, and 24 at 0; HISTOGRAM writes one column per bin, and the ``IH_*`` features return the ``--noval`` substitute with a single bin. ``--ibsi=true`` makes every texture family skip binning, except the 2D GLCM test for a constant ROI. A value that is not an integer, or whose magnitude is past 2147483647, stops the run with an error.
   * - ``--glcmAngles``
     - no
     - ``0,45,90,135``
     - Directions, in degrees, at which 2D GLCM co-occurrence matrices are computed. GLCM output has one column per angle. Values: comma-separated integers from {0, 45, 90, 135}. 2D GLCM only: 3D GLCM always uses its own fixed directions. Other integers pass parsing, but the calculation reports 'unsupported angle' for them and their columns hold 0. A non-integer list stops the run with an error.
   * - ``--glcmOff``
     - no
     - ``1``
     - GLCM co-occurrence distance in pixels. Values: integer >= 1. The value is validated but does not reach the GLCM calculation, which always uses an offset of 1.

Gabor
-----

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--gaborfreqs``
     - no
     - ``built-in pairs (see notes)``
     - Frequencies of the Gabor high-pass filters. A value f gives a wavelength of 2\*pi/f pixels. GABOR output has one column per frequency/orientation pair. Values: comma-separated real numbers; same count as ``--gabortheta``. Give ``--gaborfreqs`` and ``--gabortheta`` together, with the same number of values: value i of one pairs with value i of the other. Without both, the command line uses its built-in pairs: frequencies 0, pi/4, pi/2 and 3\*pi/4 at orientations 4, 16, 32 and 64 radians. The Python API's default set is frequencies 4, 16, 32, 64 at 0, 45, 90, 135 degrees; to compute that set from the command line, pass ``--gaborfreqs=4,16,32,64`` ``--gabortheta=0,45,90,135``. 2D only.
   * - ``--gabortheta``
     - no
     - ``built-in pairs (see --gaborfreqs)``
     - Orientations of the Gabor filters in degrees, one per frequency in ``--gaborfreqs``. Values: comma-separated real numbers in degrees; same count as ``--gaborfreqs``. Converted to radians internally; no range check is made. Give it together with ``--gaborfreqs``, with the same number of values. See ``--gaborfreqs`` for the built-in pairs. 2D only.
   * - ``--gaborgamma``
     - no
     - ``0.1``
     - Aspect ratio (ellipticity) of the Gaussian envelope of the Gabor filter. Values: real number > 0.
   * - ``--gaborsig2lam``
     - no
     - ``0.8``
     - Ratio of the Gaussian width (sigma) to the wavelength, which sets the filter's spatial-frequency bandwidth. Values: real number > 0.
   * - ``--gaborkersize``
     - no
     - ``16``
     - Width and height, in pixels, of the square Gabor convolution kernel. Values: integer >= 2. 1 is accepted but reads past the end of the convolution buffer, so its values are arbitrary (known defect, https://github.com/PolusAI/nyxus/issues/506).
   * - ``--gaborf0``
     - no
     - ``0.1``
     - Frequency of the low-pass Gabor filter that produces the baseline image the high-pass responses are compared against. Values: real number > 0. Same units as ``--gaborfreqs``: the wavelength is 2\*pi/f pixels. 2D only.
   * - ``--gaborthold``
     - no
     - ``0.025``
     - Threshold on the ratio of filtered image to baseline; pixels above it are counted in the GABOR feature. Values: real number. Any real number is accepted, with no range check. A non-numeric value stops the run with an error. 2D only.

Image handling
--------------

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--fpimgmin``
     - no
     - ``0.0 (used only when an --fpimg* option is given; otherwise each image's own minimum)``
     - Lower end of the intensity range that floating-point images are rescaled from before conversion to integer grey levels. Values: real number, less than ``--fpimgmax``. Giving any of ``--fpimgmin``, ``--fpimgmax`` or ``--fpimgdr`` switches every float image from its own scanned min/max to the fixed range [``--fpimgmin``, ``--fpimgmax``]. Unset ends then default to 0 and 1. A min that is not below the max stops the run with an error. Integer images are not affected.
   * - ``--fpimgmax``
     - no
     - ``1.0 (used only when an --fpimg* option is given; otherwise each image's own maximum)``
     - Upper end of the intensity range that floating-point images are rescaled from before conversion to integer grey levels. Values: real number, greater than ``--fpimgmin``. See ``--fpimgmin``: giving any ``--fpimg``\* option replaces each image's own range with the fixed [min, max] range. A non-numeric value stops the run with an error.
   * - ``--fpimgdr``
     - no
     - ``10000``
     - Number of integer grey levels that floating-point intensities are rescaled into. Values: integer >= 1. Giving only ``--fpimgdr`` also switches float images to the fixed range 0 to 1 (the ``--fpimgmin``/``--fpimgmax`` defaults) instead of each image's own range. Pair it with ``--fpimgmin`` and ``--fpimgmax``.
   * - ``--preserve-hu``
     - no
     - ``false``
     - Loads floating-point and rescaled DICOM/NIfTI images with one grey level per intensity unit (offset by the image minimum) instead of min-max rescaling or the stored-integer map. Values: true \| false \| t \| f (case-insensitive). Not needed to get Hounsfield units in the output: intensity features are reported in the image's own units either way. '1', 'on' and 'yes' are rejected with an error. Shape and texture features are unaffected.
   * - ``--anisox``
     - no
     - ``1``
     - Size of a pixel or voxel along x relative to the other axes. Geometric features use it: a volume (3D or 2.5D) is featurized on its voxels as acquired and the shape features scale their coordinates by the anisotropy, and a 2D slide's geometric features are computed on its pixels resampled by the anisotropy. Intensity and texture features are computed on the pixels or voxels as acquired, so they report the same values with or without anisotropy. On a 2D slide the intensity-weighted geometric features (``EDGE_*``, WEIGHTED_CENTROID_X/Y, MASS_DISPLACEMENT, ``IMOM_*``, the radial distribution and ZERNIKE2D) are computed on the pixels as acquired, each at its position scaled by the anisotropy. Of the image quality features only POWER_SPECTRUM_SLOPE changes: it is computed on the resampled ROI (known defect, https://github.com/PolusAI/nyxus/issues/519). Values: real number. A value of 1 counts as unset. No positivity check is made. A value other than 1 in any ``--aniso``\* option replaces the physical spacing of ``--use-physical-spacing`` on all three axes; the axes not given then use 1. A non-numeric value stops the run with an error.
   * - ``--anisoy``
     - no
     - ``1``
     - Pixel/voxel scale factor along y; same behavior as ``--anisox``. Values: real number. A value of 1 counts as unset. No positivity check is made.
   * - ``--anisoz``
     - no
     - ``1``
     - Voxel scale factor along z for 3D volumes; same behavior as ``--anisox``. Values: real number. Only 3D processing uses it. A value of 1 counts as unset.
   * - ``--use-physical-spacing``
     - no
     - ``false``
     - In 3D, uses each volume's OME PhysicalSize values, scaled so the smallest axis is 1, as the voxel spacing by which the shape features scale their coordinates. Values: true \| t \| 1 \| on \| yes (case-insensitive); any other value means false. 3D only. Any ``--aniso``\* value other than 1 replaces the physical spacing on all three axes. Invalid values are not reported; they silently mean false. Physical spacing columns are written to the output whether or not this is on.

Nested ROIs
-----------

.. list-table::
   :header-rows: 1
   :widths: 22 10 16 52

   * - Option
     - Required
     - Default
     - Description
   * - ``--hsig``
     - no
     - —
     - Text that marks the channel number in mask file names (for example '_c' in p0_y1_r1_c1.ome.tiff). Nested-ROI analysis uses it to find the parent and child masks of the same image. Values: string (channel marker in file names, e.g. _c). Nested-ROI analysis runs only when all four of ``--hsig``, ``--hpar``, ``--hchi`` and ``--hag`` are given. If any is missing, the others are silently ignored. 2D only. The analysis reads back the per-image CSV files, so use ``--outputType=separatecsv``: with singlecsv each parent's row is taken from the first row with its label in the combined file, which can belong to another image. It writes <stem>_nested_features.csv and a relations CSV to ``--outDir``.
   * - ``--hpar``
     - no
     - —
     - Channel number of the masks that provide parent ROIs. Values: integer. Needs ``--hsig``, ``--hchi`` and ``--hag`` as well. A non-integer value stops the run with an error.
   * - ``--hchi``
     - no
     - —
     - Channel number of the masks that provide child ROIs. A child is a ROI whose bounding box lies inside a parent's bounding box. Values: integer. Needs ``--hsig``, ``--hpar`` and ``--hag`` as well. A non-integer value stops the run with an error.
   * - ``--hag``
     - no
     - —
     - How the features of a parent's children are combined into the parent's row. NONE lists every child's features side by side. Values: SUM \| MEAN \| MIN \| MAX \| WMA \| NONE (uppercase only). Uppercase only. WMA computes the same unweighted mean as MEAN. There is no default: nested-ROI analysis runs only when all four nested options are given.
