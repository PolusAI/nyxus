# Regenerating the 2D GLDM oracle goldens

Offline; CI never invokes the generator. Run from the repository root.

## Environment

```
conda create -n nyxus_oracle -c conda-forge python=3.9 pyradiomics simpleitk
conda activate nyxus_oracle
```

PyRadiomics 3.0.1 needs Python <= 3.9. `radiomics.__version__` reports the version the generator
prints.

## PyRadiomics — `test_2d_gldm_pyradiomics.h`

```
python tests/vetting/oracles/gen_gldm_pyradiomics.py
```

Expect `70 verified, 0 failed, 0 unproducible`. The generator prints both paste-ready tables, then
re-verifies every golden pinned in the header — the 14 four-slice means and the 56 per-slice values —
and exits non-zero on a mismatch or on a pin it cannot produce.

**Two tables, because a mean cannot vet the four values behind it.** PyRadiomics computes each slice
on its own; the averaging is the generator's, not the tool's. `gldm_2d_pyradiomics_slice_ref_vals`
pins the per-slice values (keyed `<feature>_z<slice>`) and `gldm_2d_pyradiomics_ref_vals` the means,
and every assertion checks both. Regenerating one without the other leaves half the header
unverified — the generator will say so and exit non-zero.

**Fixture.** The four IBSI digital-phantom slices, read out of `tests/test_data.h` through
`oracles/ibsi_phantom.py`, so the generator and the C++ tests share one copy of the voxels. Each
slice is featurised on its own and the per-feature values are averaged over the four — that is what
`assert_gldm_mean_against_golden_values()` does on the Nyxus side, and the goldens must match
that aggregation, not a single-volume run.

**Config** (recipe `gldm.ibsi_phantom_2d`):

```python
gldm.RadiomicsGLDM(image, mask, binWidth=1, force2D=True, force2Ddimension=0,
                   gldm_a=0, distances=[1], label=1,
                   interpolator=None, resampledPixelSpacing=None)
```

`binWidth=1` is identity binning on the integer phantom, so neither tool discretises and both build
the matrix over the levels 1..6 the phantom already has. `gldm_a=0` with `distances=[1]` is the
alpha=0, d=1 coarseness Nyxus computes with `IBSI=true`. `force2D` keeps the neighbourhood inside
the slice; without it PyRadiomics would use a 3D kernel on a one-slice volume and reach for
neighbours that do not exist.

Feed the arrays through `sitk.GetImageFromArray(a[None, :, :])` — PyRadiomics wants a 3D image even
in `force2D`.

**Name mapping.** PyRadiomics spells the same quantities long-form:

| Nyxus | PyRadiomics | | Nyxus | PyRadiomics |
|---|---|---|---|---|
| `GLDM_SDE` | `SmallDependenceEmphasis` | | `GLDM_GLN` | `GrayLevelNonUniformity` |
| `GLDM_LDE` | `LargeDependenceEmphasis` | | `GLDM_DN` | `DependenceNonUniformity` |
| `GLDM_LGLE` | `LowGrayLevelEmphasis` | | `GLDM_DNN` | `DependenceNonUniformityNormalized` |
| `GLDM_HGLE` | `HighGrayLevelEmphasis` | | `GLDM_GLV` | `GrayLevelVariance` |
| `GLDM_SDLGLE` | `SmallDependenceLowGrayLevelEmphasis` | | `GLDM_DV` | `DependenceVariance` |
| `GLDM_SDHGLE` | `SmallDependenceHighGrayLevelEmphasis` | | `GLDM_DE` | `DependenceEntropy` |
| `GLDM_LDLGLE` | `LargeDependenceLowGrayLevelEmphasis` | | | |
| `GLDM_LDHGLE` | `LargeDependenceHighGrayLevelEmphasis` | | | |

**Do not regenerate at the production config.** With `IBSI=false` Nyxus re-bins the ROI with the
MATLAB scheme at `coarse_gray_depth`, while PyRadiomics bins at `binWidth=1` over the values it is
handed. The two then build their dependence matrices over different level assignments and disagree
by up to 108%; the measurement is in `gldm_2d_pyradiomics_vetting_report.md`. That config is
drift-pinned only, in `test_2d_gldm_regression.h` and `tests/python/test_2d_gldm_mechanics.py`.

## IBSI consensus — `test_2d_gldm_ibsi.h`

Those goldens are transcribed from the IBSI reference manual (pages noted per feature in the table)
and are not regenerated by a tool. They are quoted to **three significant figures**, which sets that
file's `rel=1e-2` tolerance — the measured worst case is 0.45% on `GLDM_GLN` (10.2 published against
10.2464 computed). Pin exact digits against PyRadiomics instead; the two files are complementary.

IBSI publishes them in its **NGLDM** table, which is the same statistic; see
`gldm_2d_ibsi_vetting_report.md` for the mapping and how to check the transcription against the copy
already in `test_2d_ngldm_ibsi.h`.

## Regression pins — `test_2d_gldm_regression.h`

Not oracle values: Nyxus output on the `cat2500` fixture at `GREYDEPTH=128`, `PIXELDISTANCE=5`,
`ibsi=false`. To re-record them after an intended math change, read the values off a run at those
settings — `gldm_2d_feature_value(cat2500_int, cat2500_seg, ..., make_gldm2d_settings(false), f)` is
the same call the test makes — and state in the PR why the values moved. A drift guard re-pinned
without that reason is not a guard.
