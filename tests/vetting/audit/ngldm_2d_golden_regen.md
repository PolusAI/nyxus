# Regenerating the 2D NGLDM oracle goldens

Offline; CI never invokes the generator. Run from the repository root.

## Environment

```
conda create -n nyxus_mirp -c conda-forge python=3.12 numpy
conda activate nyxus_mirp
pip install mirp==2.6.0
```

mirp exposes no `__version__`; read it with `importlib.metadata.version("mirp")`, which is what the
generator does. It also logs at INFO onto stdout, straight into the golden table — the generator
calls `logging.disable(logging.INFO)` before importing it.

## mirp — `test_2d_ngldm_mirp.h`

```
python tests/vetting/oracles/gen_ngldm_mirp.py
```

Expect `17 verified, 0 failed, 0 unproducible`. The generator prints the paste-ready table, then
re-verifies every golden pinned in the header and exits non-zero on a mismatch or on a pin it cannot
produce.

**Fixture.** The four IBSI digital-phantom slices, read out of `tests/test_data.h` through
`oracles/ibsi_phantom.py`, so the generator and the C++ tests share one copy of the voxels. Each
slice is featurised on its own and the per-feature values are averaged over the four — that is what
`assert_ngldm_feature_against_golden_values()` does on the Nyxus side, and the goldens must match
that aggregation, not a single-volume run.

**Config** (recipe `ngldm.ibsi_phantom_2d`):

```python
mirp.extract_features(image=slice_3d, mask=mask_3d, by_slice=True,
                      base_discretisation_method="none",   # phantom is already discrete 1..6
                      ngldm_distance=1.0, ngldm_difference_level=0.0)
```

`ngldm_distance` and `ngldm_difference_level` must be **floats** — mirp raises
`TypeError: ... expected to contain floating point values of 1.0 or greater` on ints. The pair
`(d=1, alpha=0)` is the coarseness the IBSI NGLDM definition uses and what Nyxus computes in IBSI
mode.

**Column mapping.** mirp suffixes each column with its configuration (`_d1_a0.0_2d`), so match on
the stem and take the `_d1` variant:

| Nyxus | mirp stem | | Nyxus | mirp stem |
|---|---|---|---|---|
| `NGLDM_LDE` | `ngl_lde` | | `NGLDM_GLNU` | `ngl_glnu` |
| `NGLDM_HDE` | `ngl_hde` | | `NGLDM_GLNUN` | `ngl_glnu_norm` |
| `NGLDM_LGLCE` | `ngl_lgce` | | `NGLDM_DCNU` | `ngl_dcnu` |
| `NGLDM_HGLCE` | `ngl_hgce` | | `NGLDM_DCNUN` | `ngl_dcnu_norm` |
| `NGLDM_LDLGLE` | `ngl_ldlge` | | `NGLDM_GLV` | `ngl_gl_var` |
| `NGLDM_LDHGLE` | `ngl_ldhge` | | `NGLDM_DCP` | `ngl_dc_perc` |
| `NGLDM_HDLGLE` | `ngl_hdlge` | | `NGLDM_DCV` | `ngl_dc_var` |
| `NGLDM_HDHGLE` | `ngl_hdhge` | | `NGLDM_DCENT` | `ngl_dc_entr` |
| | | | `NGLDM_DCENE` | `ngl_dc_energy` |

Note mirp writes `lge`/`hge` where Nyxus writes `LGLE`/`HGLE`, and `perc`/`entr`/`energy` where
Nyxus writes `P`/`ENT`/`ENE` — the abbreviations do not line up, so map by meaning, not by string
similarity.

**Do not regenerate as oracle values:** `NGLDM_GLM` and `NGLDM_DCM`. mirp has no grey-level-mean or
dependence-count-mean column because neither is an IBSI NGLDM feature. They are regression
snapshots in `test_2d_ngldm_regression.h`.

## IBSI consensus — `test_2d_ngldm_ibsi.h`

Those goldens are transcribed from the IBSI reference manual (pages noted per feature in the table)
and are not regenerated by a tool. They are quoted to **three significant figures**, which sets that
file's `rel=1e-2` tolerance — the measured worst case is 0.45% on `NGLDM_GLNU` (10.2 published
against 10.2464 computed). Pin exact digits against mirp instead; the two files are complementary.

## Coverage artifact

```
python tests/vetting/audit/scan_ngldm_coverage.py           # rewrite
python tests/vetting/audit/scan_ngldm_coverage.py --check   # drift + acceptance check
```

`--check` enforces the family acceptance rule: no `vetted` row without an oracle assertion, no row
naming an oracle nothing compares against, and `current_test` naming exactly the files that cover
the feature. Its limit is the same as every other checker's — it attributes an oracle from the test
function's name suffix, so it cannot tell an oracle test asserting real tool output from one
asserting a snapshot. Only running the generator does that.
